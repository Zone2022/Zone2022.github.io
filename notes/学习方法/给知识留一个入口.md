# 给知识留一个入口

记笔记不只是保存信息，更是在为未来的自己搭建一条可以重新走进去的路径。

> 示例文档 · 用于测试段落、引用、任务列表和文档间链接，不代表 Lynn 的真实学习记录。

## 先记录问题

一份值得回看的笔记，往往从一个具体的问题开始。比起“今天学习了什么”，试试问自己：“今天的哪个问题，让我停下来想了一会儿？”

问题足够具体，后面的材料才有放置的位置。一次实验的异常、一个概念的边界，或者一段代码为什么能工作，都可以成为入口。

## 用自己的话重写

阅读原文时的理解，和离开原文后的理解，并不总是一回事。试着暂时合上资料，只用自己的语言解释一遍。

> 当一句话很难说清楚，那里可能正是下一次学习的起点。

### 一个简单模板

```markdown
# 我想解决的问题

## 目前的理解
用几句话说明，不急着写得完美。

## 一个具体例子
让抽象概念落到可以观察的事情上。

## 仍然不确定
留下边界、反例和疑问。

## 下一步
写一个真正可以执行的小动作。
```

## 建立连接，而不是堆积

两篇手记之间的链接，可以记录“为什么它们有关”。一个没有说明的链接是地址；一句连接的理由，才是理解。

例如，阅读[浏览器的渲染旅程](../前端实验/浏览器的渲染旅程.md)后，可以继续观察界面动效如何影响注意力。一个技术问题就这样连接到了设计问题。

## 每周回看一次

- [x] 找到一篇已经不太记得的手记
- [x] 用一分钟复述它的核心问题
- [ ] 增加一个新的例子
- [ ] 把仍然不确定的地方标出来
- [ ] 给下一次学习留一个小任务

不需要把每一篇都整理成教程。能帮助自己继续前进，就已经有价值。
