# 浏览器的渲染旅程

从一份 HTML 到眼前的页面，浏览器经历了哪些步骤？从这个问题开始，理解一次像素的诞生。

> 示例文档 · 用于测试代码块、表格、目录和长文阅读体验，不代表 Lynn 的真实学习记录。

## 从结构到像素

我们写下的是文档，浏览器绘制的是像素。它先解析 HTML 和 CSS，再计算可见元素的位置与尺寸，随后绘制文字、颜色、边框等内容，最后完成合成。

这条路径可以简化为：**解析 → 样式计算 → 布局 → 绘制 → 合成**。真实浏览器有缓存、增量更新和更多优化，这个模型用来帮助入门。

### 布局关心什么

布局回答“每个元素在哪里、有多大”。改变内容、字体或者宽度，都可能影响其他元素的位置。一个段落多出一行，后面的内容也会向下移动。

### 绘制关心什么

绘制处理“看起来是什么样”。文字、边框、背景和阴影会转化为绘制指令。合成则负责将不同层的内容组合到一起。

## 用一个按钮做实验

下面的示例让按钮在悬停时轻轻抬起。动画选择 `transform`，减少对周围布局的影响。

```css
.button {
  transform: translateY(0);
  transition: transform 180ms ease-out;
}

.button:hover {
  transform: translateY(-3px);
}

@media (prefers-reduced-motion: reduce) {
  .button { transition: none; }
  .button:hover { transform: none; }
}
```

**并不是用了 transform 就一定流畅。** 页面内容、图层数量、设备性能都会影响结果。可以通过开发者工具观察真实开销，再决定是否需要优化。

## 三种改变，对照观察

| 改动 | 观察重点 | 适合记录的问题 |
| --- | --- | --- |
| 改变容器宽度 | 周围元素是否重新排布 | 哪些内容受到了影响？ |
| 改变背景颜色 | 绘制区域是否变化 | 是否只重绘了需要变化的部分？ |
| 改变 transform | 位移与合成开销 | 动画是否稳定、是否产生过多图层？ |

## 一次小练习

1. 创建一个包含文字和图片的卡片。
2. 分别用 `margin-top` 和 `transform` 做悬停效果。
3. 在开发者工具中录制交互过程。
4. 观察布局、绘制和帧率，而不只凭感觉判断。
